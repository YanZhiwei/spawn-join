# Python Package Release

The repository contains nine independent Python distributions. The root
`pyproject.toml` is tool-only and is not published.

## Versioning

Development releases use PEP 440 versions such as:

```text
0.1.0.dev0
0.1.0.dev1
```

Do not reuse a published version. Increment the `.devN` suffix before a new
publication. Distribution names remain stable; do not add `-dev` to the package
name.

## Why not GitHub Packages

GitHub Packages has no Python registry. Only Container, npm, RubyGems, Maven,
Gradle and NuGet are supported, and the Python/PyPI registry request was closed
as "no longer planned" (github/roadmap#94). Uploading a wheel to
`https://pypi.pkg.github.com/<owner>/` therefore returns `404 Not Found` no
matter which token or package setting is used.

## Publishing model

Distributions are published on GitHub in two parts:

1. **GitHub Release assets** hold the wheels and sdists.
2. **A static PEP 503 index on GitHub Pages** (branch `gh-pages`) links to those
   assets, so `pip` and `uv` can resolve and download them.

The workflow is `.github/workflows/publish-package.yml`. Run it from the
Actions page and choose one package or `all`. `all` builds in dependency order:

1. `spawn-join-core`
2. `spawn-join-common`
3. `spawn-join-llm-provider`
4. `spawn-join-llm-provider-langchain`
5. `spawn-join-llm-channel`
6. `spawn-join-llm-model-sync`
7. `spawn-join-agent-deepagents`
8. `spawn-join-agent-work`
9. `spawn-join-personal-assistant`

Each package is locked, synced, checked by the existing quality entry point, and
built in isolation. The artifacts are uploaded to the release named by the
`release_tag` input, the index is regenerated from every non-draft release, and
the result is force-pushed to `gh-pages`. The workflow needs only
`contents: write`; no personal token is stored in the repository.

The index is generated by `scripts/build_pypi_index.py`, which normalizes names
per PEP 503, skips drafts, and appends the asset SHA-256 digest as a link
fragment when GitHub reports one.

## Consuming the packages

Packages without third-party dependencies resolve from this index alone:

```bash
pip install --index-url https://yanzhiwei.github.io/spawn-join/simple/ spawn-join-core
```

Packages that depend on `pydantic`, LangChain, `openai` and similar also need
PyPI. `uv` refuses ambiguous matches unless you opt in explicitly:

```bash
uv pip install \
  --index-url https://yanzhiwei.github.io/spawn-join/simple/ \
  --extra-index-url https://pypi.org/simple \
  --index-strategy unsafe-best-match \
  spawn-join-llm-provider
```

```bash
pip install \
  --index-url https://yanzhiwei.github.io/spawn-join/simple/ \
  --extra-index-url https://pypi.org/simple \
  spawn-join-llm-provider
```

Prefer `--index-url` alone when the package has no third-party dependencies:
combining indexes lets a public index shadow a name here (dependency
confusion), which is why `uv` requires `unsafe-best-match` to accept that risk.
Pin exact versions (`spawn-join-core==0.0.1.dev0`) when reproducibility matters.

A single wheel can also be installed straight from the release:

```bash
pip install https://github.com/YanZhiwei/spawn-join/releases/download/python-0.0.1.dev0/spawn_join_core-0.0.1.dev0-py3-none-any.whl
```

Limitations:

- GitHub Pages sites are public, so this is not a private index.
- Pages allows one site of at most 1 GB with files up to 100 MB; the nine
  distributions are far below that.
- Re-running the workflow with the same tag replaces the assets (`--clobber`)
  and rebuilds the index, so consumers must use the current version.

## Local verification

From the repository root:

```powershell
pwsh -NoProfile -File scripts/quality.ps1 -Package spawn-join-core
pwsh -NoProfile -File scripts/quality.ps1 -Check docs
pwsh -NoProfile -File scripts/quality.ps1 -Check governance
```
